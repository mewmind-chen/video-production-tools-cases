# 钢笔淡彩代码动画：制作方法与两版实测

整理日期：2026-10-20。本文记录当前会话的制作方法、样片实现和失败经验，不代表已还原参考 MV 的完整效果。

## 交付内容与实际状态

- [样片说明及运行方法](../examples/ink-watercolor/README.md)
- [第一版 Canvas 样片](../examples/ink-watercolor/v1/preview.html)：12 秒，静态街景为主，叠加雨丝、涟漪与轻微镜头推进；用户反馈运动不足，不符合预期。保留作失败对照。
- [第二版 SVG 样片](../examples/ink-watercolor/v2/play.html)：16 秒，245 条路径逐笔生长、淡彩渐入、人物腿部摆动与前进、雨伞和衣摆运动；修复了预览环境自动播放停止的问题。
- 两版均是 HTML 实时动画，无配乐、无 MP4 成片。第二版仍为技术原型，非高质量叙事动画成品。
- 本次归档仅包含制作方法与自制样片，不包含用户私人故事、对话或参考视频下载文件。

## 1. 制作流程

故事 → 剧本 → 分镜 → 角色与场景 → 路径与图层 → 动画时间轴 → 动态验收 → 固定帧率导出 → 配音配乐合成。

故事制作须先列出每个事件的起因、行动、结果与关系变化，再决定镜头。车站背景配旁白不能替代到站、检票、拥抱、松手、离开的动作过程。长故事按章节制作，不为塞进一首歌删掉重要情节。

代码动画可使用外部立绘、照片，也可全部代码绘制。本次样片没有使用外部图片或模型生成图片。

## 2. 技术选型

| 技术 | 使用位置 | 限制 |
|---|---|---|
| SVG | 路径生长、轮廓、图层角色、道具 | 大量 DOM 属性更新可能影响性能 |
| Canvas 2D | 纸纹、水彩、粒子、倒影、最终合成 | 需要自己管理路径、图层和命中区域 |
| WebGL / Three.js | 大量粒子、复杂水面、空间摄影机 | 普通二维叙事不必引入这部分复杂度 |
| FFmpeg | 音画合成、字幕、编码 | 角色动画需先由渲染器产生 |

推荐以 SVG 实现画线和角色，以 Canvas 补充纹理、天气及合成，实际依复杂度选择，不必混用所有技术。

## 3. 钢笔逐笔绘制

先把建筑轮廓、窗框、窗棂、排线和人物轮廓拆成独立路径，每条记录开始时间、持续时长、线宽和颜色。

```js
const length = path.getTotalLength();
const progress = Math.max(0, Math.min(1, (t - start) / duration));
path.style.strokeDasharray = length;
path.style.strokeDashoffset = length * (1 - progress);
path.style.visibility = progress === 0 ? 'hidden' : 'visible';
```

`progress` 从 0 到 1，线条沿路径逐渐出现。隐藏未开始的路径可避免圆头线帽残点。完成绘制后，正式项目可清除虚线样式，避免复杂路径的虚线端点伪影。

顺序决定观感：轮廓较慢，短排线较快，几组笔画可以并行。主体人物和道具也需要有绘制过程，不能只给字幕、边框加画线。

可用 `getPointAtLength(length * progress)` 获取当前笔尖位置。样片第二版保留可视化笔尖作为技术演示；正式影片一般无需大号悬浮钢笔。

## 4. 钢笔与淡彩的质感

钢笔：轻微变线宽、断笔、复描、局部排线；近景重、远景轻；避免全部机械直线。

水彩：多层低透明度色块、不规则边缘、积色、叠色和留白。通过局部遮罩扩散表现上色，而非全画面统一渐显。少量越过轮廓可增加手绘感。

纸纹与水彩形状使用固定随机种子或预生成图层。每帧重新随机会导致纹理闪烁。

当前 v2 的颜色实现为分块透明度渐入与过渡模糊，尚未实现真实水彩扩散。实现完整效果需补充纹理遮罩、扩散边缘与局部积色，不能把现有渐显称为完成的水彩模拟。

## 5. 人物动作

角色分为头、发、躯干、衣摆、上下臂、手、大小腿、脚；相机、伞、行李另建图层。设置旋转支点，再用关键帧或骨骼控制。

| 动作 | 必要处理 |
|---|---|
| 行走 | 髋膝踝、交替落脚、重心与地面接触 |
| 转头 | 朝向与中间姿态、头发随动 |
| 递物 | 肩肘腕、接触、持有权转移、松手 |
| 牵手 | 接近、接触、握住、共同运动 |
| 拥抱 | 双人姿态、身体接触、手臂环抱与停留 |

二维部件旋转不足以表现大角度转身，需要补画姿态。第二版只做了简化腿部旋转、整体前进、伞面与衣摆运动，未达到自然步态。不可把剪纸平移当完整角色表演。

## 6. 环境与镜头

雨丝分远近，速度、长度、透明度不同；涟漪从小到大并衰减；倒影翻转、压缩后做横向扰动或切片；风驱动头发、衣摆和伞面，但振幅不同。

镜头用分层视差、推近、跟随，服务事件。主体必须有可辨识动作，不能靠镜头缩放掩盖人物不动。

## 7. 统一时间轴与确定性渲染

每场记录起止时间、画线与上色顺序、角色动作、镜头、字幕、声音和转场。统一接口：

```js
window.DURATION = 16;
window.renderFrame = function (t) {
  // 全部状态从 t 计算；相同 t 得到相同画面。
};
```

不要依赖前一帧累积状态。长片按镜头拆模块，总调度器将全局时间转换为镜头局部时间。改一场不需重写全片。

配乐应在获得实际音频版本后做乐句对齐，不臆测高潮时间。旁白和对白段压低配乐，并为脚步、快门、车站等环境声保留空间。归档样片未接入音频。

## 8. 实测问题与验收

### 静态帧通过，不代表动画播放通过

第一版只检查不同时间静态帧，未先检查持续播放。预览环境中 `requestAnimationFrame` 未持续触发，用户看到近似静止画面。第二版改为 `setInterval` 配合实际经过时间驱动；实测播放从 10.0 秒变到 10.8 秒，腿部角度同时改变。

这只是当时环境的结果，不能推广为所有浏览器的行为。常规浏览器优先使用 `requestAnimationFrame`，必要时检测停滞并提供定时回退；页面在后台时，定时器仍可能被系统限制。

### 缓存

本地预览曾读到旧 JS，导致修改未生效。使用版本化文件名或可靠的缓存策略。当前可播放入口 v2/play.html 引用 motion-fixed.js，便于定位已验收版本。

### 动态验收清单

1. 打开后秒数持续变化。
2. 相隔一秒的主体位置、关节状态改变。
3. 实际播放观察画线、动作、转场与停顿。
4. 暂停、拖动、重播、循环正常。
5. 手机上检查流畅度、文字和触控。
6. 导出后检查音画同步与完整时长。

## 9. 导出视频

按固定帧率逐帧设定 t，而非依赖屏幕播放速度录制：

```js
for (let frame = 0; frame < totalFrames; frame++) {
  renderFrame(frame / fps);
  // 捕获画面，写入帧序列或编码管线。
}
```

然后用 FFmpeg 合成音频并编码。检查分辨率、帧率、总帧数、音画同步、字幕及片尾。本次没有完成渲染导出脚本与 MP4，不将实时网页描述成已交付视频。
